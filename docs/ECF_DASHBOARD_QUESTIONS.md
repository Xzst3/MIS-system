## Reporting rules

- Date presets use the foundation's current date in Asia/Shanghai. Business DATE fields remain ISO dates without a timezone shift.
- Complete-month comparisons use preceding complete calendar months. Other bounded presets/custom dates compare the immediately preceding equal number of inclusive days. Both dates and comparison basis are displayed. All-time reports have no artificial earlier comparison.
- Summary, comparison, monthly activity and breakdown queries use the full matching database population, independently of the 25-row screen pagination. Main report queries run together in a repeatable-read transaction.
- Export all matching rows using the same filters, up to 20,000 rows per file. If more match, return an explicit error and ask for narrower filters instead of silently truncating the file. Cash amounts export in USD units; database storage remains integer cents.
- A monthly activity bar counts matching records, including all selected statuses. The monetary/approved-hours metrics explicitly exclude non-posted/non-approved entries. Asset inventory is an as-of closing position rather than monthly sales activity.
- Roles apply on the server to queries and exports. Coordinators see their submitted finance requests and no donor identity. Fundraising can see contribution source amounts and aggregate impact but not beneficiary identities. Finance sees financial evidence, not the full beneficiary-history report or other staff's hours. Volunteers cannot open this report centre.
- Source-lot attribution is an accounting explanation retained in the ledger. It does not claim that an identifiable physical banknote moved to an individual. Shared costs retain their actual purpose.

## Neon records for donor-to-use trace

`finance_requests` stores unique references, business date, donor/person, source/fund, service/item and submitted/reviewed actors. `finance_lots` anchors original donor and donated-asset provenance. `finance_postings` stores each signed, source-specific fund movement. `inventory_items` and `inventory_movements` keep noncash receipts/distributions/sales. `service_records` link the beneficiary and programme. `audit_log` records submission and approval actions.

The additive `ecf_funding_provenance` view joins these actual records without copying or recomputing a second ledger. It includes original receipt ID, original donor person ID, cash source ID, transaction ID, fund, signed cents, business date, service/beneficiary and review evidence. `/api/funding-trace` queries all applicable movements for reconciled totals and paginates the detail. Its summary therefore does not depend on the older finance screen's latest-3,000-posting list.

Example read-only SQL for the Neon SQL editor (replace the reference with the desired posted contribution or original asset receipt):

```sql
SELECT original_donation_reference, cash_source_reference, donor_name,
       event_date, transaction_reference, kind, fund_name, delta_cents,
       description, service_title, beneficiary_name,
       submitter_name, reviewer_name, reviewed_at, review_note
FROM ecf_funding_provenance
WHERE original_donation_reference = 'ECF-2026-GIFT-OLIVIA'
ORDER BY event_date, posting_id;
```
